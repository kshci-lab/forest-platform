# SharePoint研究MT・全体MT連携

## 実装状況と未確認事項

既存の概要・共通フィルタ・集計表・棒/折れ線グラフ・CSVに追加。SharePoint本文は取得しない。MySQLのデータ・スキーマも変更しない。PHP 7.4以上、cURL、OpenSSL、JSONが必要（既存ダッシュボードはPDO MySQLも使用）。

大学テナント・対象サイトURL・ドライブID・親フォルダID・大学のアプリ承認方針は未提供で、実フォルダへの接続は未検証。ローカルにSharePoint認証設定はない。テスト用の疑似Graph応答で取得・集計・障害保持を検証する。サンプル結果を実データとして画面に投入しない。

## 集計定義

- 親フォルダIDで `0010-研究MT` と `0011-全体MT` を固定し、同期のたびに親名・フォルダ属性を検証する。
- 親直下のフォルダ名の先頭 `YYYY-MM-DD` を実在日付として検証し、実施日に使う。`2026-06-22_全体MT` は有効、`2026-02-30` は無効。
- 日付フォルダの**直下**の実ファイルのみ。下位フォルダとショートカット（remoteItem）は探索・計上しない。サブフォルダまで必要なら確認後に拡張する。
- 研究MT実施件数：ドライブID・日付フォルダID・最後の拡張子を除いた完全一致名で各1件。大小文字・全半角・修正版・最終版は推測で統合しない。同日の別フォルダは別開催。別日の同名資料も別件。
- 研究MT元ファイル数：上記をまとめる前の対象ファイル数。研究MT開催日数は日付フォルダ数（同日名の別IDも別フォルダとして数える）。
- 全体MT開催回数：日付フォルダ数。教訓共有件数：対象ファイルIDごとに1件。PDFとPPTXも各1件。
- 空の日付フォルダは開催1件、資料/共有0件。親直下ファイル・日付形式外のフォルダは対象外。
- 共通の明示的除外：`~$`で始まる名前、末尾`~`、拡張子`.tmp`/`.temp`（大小文字無視）、`.DS_Store`/`Thumbs.db`/`desktop.ini`（大小文字無視）。除外ファイル・対象外項目の件数を同期状態に表示。
- MTの期間・年月日週集計は常に実施日基準。既存の「作成日時/更新日時」切替はMTには適用しない。

## 参加者の確認済み対応表

`participants.file_ids` に `"ドライブID:ファイルID": "users.user_id"`、または `participants.stems` に `"拡張子を除く完全一致名": "users.user_id"` を追加する。管理者が資料の発表者/共有者を確認した場合だけ記入する。更新者/作成者・部分一致・姓の推測・本文解析は使わない。

ファイルID指定は名前指定より優先。研究MTの複数形式のうち確認済みの参加者が1人ならその人とする。異なる参加者の確認済み対応が混在する場合は「未判定（対応矛盾）」にする。存在しないユーザーIDも未判定。対応表を変更した場合は、次の画面取得から反映（ファイル再同期不要）。

参加者指定なし（選択解除）は未判定を含めた全資料。指定時は確認済み対象者の資料のみで、「MT資料の未判定も含める」を明示的に選ぶと未判定を追加する。開催指標は対象者の資料があるフォルダを各1件に絞り、開催そのものを個人に割り当てない。開催の参加者軸は「開催（参加者割当なし）」。空フォルダは参加者を確認できないので参加者指定時には含めない。

## 大学管理者への依頼・認証方式

自動同期は人のログインを必要としない **Entraアプリのclient credentials + 証明書** を推奨。実装は証明書による署名済みclient assertionをサポートし、大学が許可する場合は環境変数のクライアントシークレットにも対応。チャットのSharePoint接続と、サーバーのGraphアプリ認証は別設定。

大学管理者に依頼する作業：

1. 対象SharePointサイトURLと、アプリ登録・証明書・無人定期実行の許可方針を確認する。
2. 単一テナントのEntraアプリを登録し、テナントID・アプリIDを確定。公開証明書を登録する。秘密鍵はサーバーの非公開領域に保存する。
3. Microsoft Graphの**Application `Sites.Selected`** に管理者同意し、対象サイトへの **read** ロールを別途付与する。Selectedの同意だけではアクセスできない。大学管理者が権限を持つ管理用手段で `POST /v1.0/sites/{site-id}/permissions` に `roles:["read"]` と対象アプリIDを指定する。同期アプリ自身には権限付与用の管理権限を与えない。
4. メタデータGETで `GET /v1.0/sites/{hostname}:/{site-relative-path}`、`GET /v1.0/sites/{site-id}/drives` を使い、ライブラリのdrive IDを特定する（Selectedで探索不可の場合は管理者がIDを渡す）。
5. 各親フォルダについて `GET /v1.0/drives/{drive-id}/root:/{encoded-folder-path}?$select=id,name,folder,webUrl` でIDを確認する。ライブラリ内の実際のパスを使い、同名フォルダと取り違えない。
6. 上記IDを外部設定に記入し、初回同期後に管理者がフォルダ・ファイル一覧と件数を照合する。資料名と参加者の対応も確認する。

大学がアプリ権限を許可しない場合、委任認証とオフラインアクセスの承認・トークン保管/再認証設計が別途必要。現時点で大学の承認を得たとは扱わない。

公式資料：[client credentials](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-client-creds-grant-flow)、[Selected権限と明示的付与](https://learn.microsoft.com/en-us/graph/permissions-selected-overview)、[driveItem children](https://learn.microsoft.com/en-us/graph/api/driveitem-list-children?view=graph-rest-1.0)。

## サーバー設定

`sharepoint_meetings.config.example.json` を**公開ディレクトリ外**（例 `/etc/forest-platform/sharepoint-meetings.json`）にコピーして実値を設定する。設定ファイル・証明書・秘密鍵・キャッシュをGitに追加しない。ファイルをブラウザーから取得できる場所に置かない。

- PHPの実行環境に `FOREST_SP_CONFIG=/etc/forest-platform/sharepoint-meetings.json` を設定。MAMP/Apacheでは環境変数を引き継ぐ設定が必要。CLIにも同じ設定ファイルを渡す。
- `cache_dir` を事前作成し、PHP/定期同期の実行ユーザーが読み書きできるようにする。0700（同一ユーザー）または0770（同一グループ）。内部ファイルは0600で保存するため、WebとCLIは原則同じOSユーザーで実行する。
- 秘密鍵・設定は0600。証明書のパスを設定し、暗号化鍵の場合は `FOREST_SP_KEY_PASSWORD` をサーバーの秘密情報管理から渡す。
- シークレット方式の場合は証明書/秘密鍵のキーを設定から削除し、`FOREST_SP_CLIENT_SECRET` を秘密情報管理から注入する。コマンド行やJSONに秘密値を書かない。
- Webの手動同期は既存のダッシュボード認証とセッションCSRFトークンで保護。GraphのGETと認証POSTのみを使い、SharePointファイルの変更・削除はしない。
- 2つの親以下を最後のページまで取得し、正常時だけキャッシュ全体を原子的に置換する。IDを保持し、同じ同期を再実行しても加算しない。追加/削除/移動は次の完全取得に反映。途中失敗/権限切れ/HTTPエラー/不正応答では前回の正常キャッシュを保持する。
- 1回の取得は約240秒で打ち切り、前回結果を保持する。WebのPHP上限は300秒に設定するが、サーバー側の上限で短くなる場合がある。大規模フォルダで完了できない場合は取得設計の拡張が必要。通常はCLI同期を使う。同期の同時実行はファイルロックで防止する。TLSを検証し、Graphページング先をGraphホストに限定し、リダイレクトには資格情報を送らない。
- 未設定・未同期は「—」。取得済みで対象0件の場合だけ0件。最終正常同期日時は日本時間で表示。失敗後は前回の同期データであることを表示する。

## 定期同期の起動

CLIは既存MySQLに接続しない。最初に同じ実行ユーザーで手動確認する。

```sh
/path/to/php /path/to/forest-platform/scripts/sync_sharepoint_meetings.php --config=/etc/forest-platform/sharepoint-meetings.json
```

次にサーバー管理者がcron（または同等のサービススケジューラ）へ登録する。例は5分ごとに起動し、最後の正常同期から1時間未満なら取得を省略する。失敗時は次の起動で再試行する。

```cron
*/5 * * * * /path/to/php /path/to/forest-platform/scripts/sync_sharepoint_meetings.php --config=/etc/forest-platform/sharepoint-meetings.json --due >> /private/log/path/forest-meetings-sync.log 2>&1
```

実際のPHP・プロジェクト・ログパスへ置き換え、ログの読み取り権限とローテーションを設定する。サーバーのcron登録・本番設定はこの開発では実施しない。認証・対象IDが未確定のため、定期取得が稼働中とは扱わない。

## 画面とCSV

概要の4指標を押すと既存の集計・分析タブで選択する。年月日・週・参加者軸、クロス集計表と既存グラフを使用する。数値セル/棒/点を押すと、そのセル/行の正確な根拠レコードと元資料リンクを表示する。研究MTの複数形式は同じ1件の中に併記する。

既存の「集計結果CSV」は従来どおり。MT選択時の「根拠資料CSV」は資料ごとに1行（空開催は空ファイルの1行）を出力し、集計単位ID・日付フォルダID・ファイルID・URLを含む。**研究MTの根拠CSVの行数は実施件数ではない**。集計単位IDのユニーク数で実施件数を再現する。CSV数式として解釈される先頭文字は引用符で無効化する。メタデータJSONにも同期状態と指標定義が含まれる。

## 苗字による参加者照合（追加仕様）

利用者の指定により、ファイルID・拡張子を除く完全一致名の指定がない資料は、`participants.surname_aliases` の苗字表記で照合する。例：`"705669067": ["山内", "yamauchi"]`。空白なしの日本語フルネームから機械的に姓を切り出さず、登録ユーザーを確認して苗字表記を設定する。英字は大小文字を区別せず、全角英字も正規化する。英字の別の単語の一部分は一致させない（`kawa` と `nakagawa` は別）。数字・区切り記号・日本語説明が隣接する表記は対応する。

漢字はファイル名内の苗字を照合し、短い姓が長い姓の内部に含まれる場合は長い一致を優先する（江川を川に割り当てない）。同じ苗字に複数の登録者がいる場合や、資料名に複数人の苗字がある場合は未判定。既存の個別ファイル指定は苗字照合より優先し、無効なユーザーID・明示的なnull指定を苗字で上書きしない。ファイル名で発表者を対応させる運用上のルールであり、本文や更新者は使わない。反映にOneDriveの再同期は不要。
