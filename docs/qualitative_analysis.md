# 教訓の質的分析

## 開き方

データ→教訓一覧で教訓にチェックを付け、「選択した教訓を質的分析へ」へ進む。検索結果全件を選ぶ場合は「検索結果の教訓を選択」を使う。セット名と目的を入力して作成する。以後はデータ→質的分析→保存済みセットから再開する。

元の教訓と内省は読み取り専用。分析セットには取得時点の内容・理由・活用場面・文脈・所有者・論理キー・元行IDを保存する。共通フィルタで保存対象を自動変更しない。教訓追加だけ現在の抽出条件を使う。除外には理由が必要。

## 保存先・認証

非公開の `/Applications/MAMP/forest-platform-private/qualitative-analysis/analysis.sqlite`。`FOREST_QUALITATIVE_DB` 環境変数で変更可能。pdo_sqliteが必要。ディレクトリ0700、ファイル0600。Webプロセスから書込できることを確認する。MySQLやSharePointへは書込しない。

既存のログインとダッシュボード認証（または管理者権限）を確認し、USERIDを所有者にする。クライアントが送ったowner値は使わない。共有アカウントを使う場合はそのログインを使う人同士でセットを共有することになる。独立した個人アカウントを推奨。POSTは専用CSRF、SQLiteは全更新をトランザクションで実施し、revision不一致は409。通常の教訓取得APIへ論理グループIDの参照項目だけ追加する。

実行中のSQLiteファイルを単純コピーしない。運用バックアップはSQLiteの整合したバックアップまたは停止中のコピーとし、同じ非公開アクセス制限を適用する。セットJSONの出力は分析データの退避であり、イベント履歴全体のDBバックアップとは別。研究データの保存期間・削除依頼は施設の運用に従い、コピーやバックアップも対象にする。

## 操作

- 読む・分類：50行ページ、検索、参加者/日時/手動順、一括ラベル付与・解除、保留、理由付き除外、個別メモ、2〜3事例比較。
- ラベル定義：名称・定義・包含/除外・カテゴリ・廃止。意味を変えると既存付与を見直し対象にする。
- 比較・解釈：ラベル/参加者/月/起点/併存/カテゴリ。ラベルの延べ件数と教訓数を区別。カテゴリは教訓集合の和集合。表から根拠に戻れる。解釈に典型例・反例・判断困難な事例を紐付けられる。
- AI：既存チャットに利用者が貼り付ける。API料金を発生させる処理はない。20件または約30,000文字で分割する（単一の長文は1件で出力）。モデルの上限を保証する値ではない。既定で氏名と内省は出力しないが、本文中の個人情報までは自動匿名化しない。
- 依頼はJSONで保存・コピー・出力。既存ラベルだけでなくnew_labelsにtemporary_id/name/definition/include/excludeを返せる。結果を貼付またはJSONファイルで読み込み、検証→選択した正常行の仮分類取り込み→別操作で採用する。
- ID・hash・依頼ID・分割・定義版・未知ラベル・重複・欠落・手動分類の変更を検出。エラー行は適用不可、競合警告行は既定で選択しない。部分取り込み後の残りを追加でき、同一結果の再投入はno-op。
- 採用は既存分類を維持して追加する。AI由来・個別/一括を記録し、一括採用を個別精査済みとはみなさない。不要なラベルは読む画面で解除する。
- 取消は直前の未取消変更を逆操作で戻し、履歴を残す。取り込みfingerprintは残すため、取り消した結果を再び使う場合は新しい依頼を生成する。
- 履歴・固定保存：対象・定義・分類・メモを不変の版として保存し、後からJSON出力できる。現在のセット編集では保存版を上書きしない。

メモは明示的な「メモを保存」、定義・考察も保存ボタン。ラベル一括付与などは操作時に保存。未保存の入力と保存中はページ離脱時に警告し、保存失敗時は画面内入力を保持する。再読み込み前に必要なら入力を退避する。2画面での競合は再取得してから確認する。

セットのアーカイブと復元が可能。アーカイブ済みは既定一覧から非表示となり、「アーカイブも表示」から再開・復元できる。開発時の確認セットはアーカイブ済みで、元の学習記録に影響しない。

## 初期実装の範囲

教訓全体へのコード付与。ラベル統合・分割UI、文章部分へのコード、同時共同編集、Sheetsの埋め込み、自動チャット送信、L3自動評価は未実装。別案はセット複製で試せる。元教訓の現在内容は詳細で確認できるが、保存本文の最新版への自動置換は行わない。更新版を別セットとして取り直すと比較できる。

音声・資料の対応確認は既存MTの確認タブを継続利用する。DB教訓と資料内教訓候補の自動対応は行わない。解釈の根拠は初期実装ではセット内の教訓を参照する。音声発言自体への質的コードは将来拡張。
